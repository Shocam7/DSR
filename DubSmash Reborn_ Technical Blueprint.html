DubSmash Reborn: Technical Blueprint

Version 1.0 · Android-first · For engineering, product and legal

1. Vision and success criteria

Users dub songs and dialogues, and the app rebuilds their real room as the cinematic universe the audio comes from. Each user gets a different variant (one gets Harrenhal, another Winterfell) fitted to their own space.

Metric Target
First themed preview after scan ≤ 1 s (bundled base look)
Personalized look (p50 / p95) ≤ 8 s / ≤ 15 s
Preview frame rate ≥ 24 fps low tier, ≥ 30 fps mid/high
Device coverage Tier L runs on ~all Android 8+ phones with a GLES 3.0 GPU
Export fidelity Exported video matches what the user saw
Crash-free sessions ≥ 99.5%
Blended generation cost < $0.02 per session (target, validate in beta)

2. Design principles

  1. The preview never waits on the network or on ML. The render loop runs at full rate using the latest available masks and theme.
  2. Faces and raw video stay on the device. Only a compact scene descriptor (and optionally one face-excluded keyframe) is uploaded.
  3. Compose before you generate. Pooled, pre-generated assets cover most requests. Fresh generation is the exception.
  4. Degrade gracefully. Three quality tiers and a frame-time governor.
  5. Deterministic per session. Seeds and theme versions are pinned, so the same wall stays the same across frames and in the export.
  6. Rights first. Every universe is gated by a license record or switched to a generic "inspired-by" mode.

4. Android client

4.1 Threads and frame flow

  • Camera thread: CameraX Preview into a SurfaceTexture bound to an EGL external texture (zero-copy to the GPU). A separate ImageAnalysis stream at 256 to 320 px feeds the ML thread.
  • ML thread: runs models on a schedule (table below), publishes masks to a lock-free "latest result" buffer, and never blocks rendering.
  • GL render thread: draws every vsync using the latest masks and theme. Compositing is done in shaders only.
  • I/O thread: descriptor upload, theme download, cache.

Handheld camera motion is handled with cheap feature-based homography or ARCore pose when available. Version 1 optimizes for the common case of a propped-up phone.

4.2 Perception models

Task Model (starting point) Input Cadence Tier
Person mask MediaPipe selfie segmentation or custom lightweight net 256 px every 1 to 2 frames L, M, H
Scene segmentation (wall, floor, ceiling, window, furniture) SegFormer-B0 or DeepLab-MobileNet, fine-tuned to ~12 classes 160 / 256 / 320 px every 4 / 3 / 2 frames L, M, H
Object instances (bottle, cup, chair, lamp, books, plants) YOLO11n-seg or EfficientDet-Lite + optical-flow tracker 320 px every 5 frames, tracked between M, H
Face landmarks (for lip-sync scoring and face-aware relight) MediaPipe Face Landmarker face crop every frame M, H
Depth ARCore Depth where supported, else Depth Anything V2 Small 256 px 2 to 5 fps H
Lighting estimate Spherical harmonics from scan frames 64 px once, refreshed every ~5 s L, M, H

Runtime: LiteRT with INT8 models. Delegate order is NNAPI/NPU, then GPU, then XNNPACK CPU. A first-launch micro-benchmark picks the fastest working delegate per model, because some GPU drivers are slower or buggier than CPU.

All masks are smoothed temporally (exponential moving average plus edge-aware upsampling) to stop edge shimmer. Mask quality and flicker are where most tuning time will go.

4.3 Compositing stack (draw order)

  1. Camera frame (base).
  2. Surface retexturing. Wall, floor and ceiling masks get tiled PBR textures. Lighting is preserved by multiplying the texture by lum(frame) / mean_lum(region), so real shadows and gradients carry through. Perspective comes from ARCore planes when available, otherwise from vanishing-line estimation on the wall mask.
  3. Prop replacement. Fill the original object's pixels from a clean plate (a temporal median of the scan frames with the person masked out), then render the replacement (bottle → goblet) with Filament into an offscreen texture at the object's tracked box, scale and a depth-ordered position.
  4. Atmosphere. Fog, dust, embers, snow (GPU particles), a color-grade LUT, and window/sky replacement using the window mask.
  5. Person layer. Original pixels via the person mask, with a subtle theme relight (color tint, rim light) so the user looks like they belong.
  6. UI and captions.

4.4 Scene descriptor (what leaves the device)

Built during a 2 to 3 second guided scan ("Slowly show us your room"). It contains class-area percentages, object list with normalized boxes, dominant palette, lighting estimate, room-layout hints, and device tier. Its size is under 50 KB. An optional keyframe (≤ 512 px) is sent only with consent, and the person mask is applied first so no one is in it.

4.5 Tiers and frame-time governor

Tier L Tier M Tier H
Scene seg 160 px, every 4th frame 256 px, every 3rd 320 px, every 2nd
Object swap off on (≤ 3 props) on (≤ 8 props)
Depth / ARCore off optional on
Theme textures 512² ASTC/ETC2, ≤ 8 MB 1024², ≤ 16 MB 1024² + normal maps, ≤ 25 MB
Particles / 3D minimal moderate full

Tier is chosen from a device-model lookup (remote config) plus the first-launch benchmark. The governor watches rolling frame time, thermal state (PowerManager thermal status) and battery. When over budget, it drops in this order: depth, then object swaps, then mask resolution and cadence, then particles, and finally tier. It recovers gradually when headroom returns.

4.6 Dub engine (audio)

  • Playback and capture: Oboe (AAudio) for low-latency output and mic input, with echo cancellation. Users on headphones get clean voice. Speaker mode uses AEC.
  • Latency calibration: measure round-trip once per device and shift the voice track so lips and audio align in the export.
  • Cue track: each licensed audio item ships with a beat grid, lyric/dialogue timestamps and scene cues. The theme runtime uses them to sync effects (lightning on a drum hit, torchlight flicker in the rhythm, a "scene change" at a chorus).
  • Lip-sync scoring (optional game layer): mouth-open curve from face landmarks compared against the audio envelope.
  • Modes: lip-sync to original audio, voice-over dub, and duet/remix edits.

4.7 Recording and export

  • The final composited frame renders into a MediaCodec input surface (H.264/HEVC) alongside the preview. Audio is mixed (track + optional voice) and muxed with MediaMuxer.
  • The theme is frozen and version-pinned when recording starts, so the export is identical to the preview.
  • Post-process options: trim, captions and stickers via Media3 Transformer. A premium "Studio render" re-renders the clip server-side at higher quality, using the stored masks and theme.

5. The Universe system (audio → world)

Every catalog item (song or dialogue clip) links to one or more Universe Packs. A pack is the unit of content and licensing:

Component Purpose
Style bible Palette, materials, architecture motifs, lighting mood, props, forbidden elements
Variants Locations within the universe (Harrenhal, Winterfell, ...), each with an embedding and scene-fit tags (indoor/outdoor, size, brightness, clutter)
Base look Bundled with the track download: LUT, fog settings, 3 low-res textures, ambient loop. This is the instant first look
Prompt templates Per surface and per prop, with negative prompts
Asset pools Pre-generated textures and .glb props, tagged and embedded
Cue track Beat grid, line timestamps, scene cues
Rights record License ID, territories, expiry, allowed mode (licensed or inspired)

Variant selection. Score each variant as fit(scene, variant) + novelty(user history) + exploration, then sample with a seeded softmax. Variants stay sensible (a windowless room tends toward a dungeon, a bright room with windows toward a great hall) while different users still land on different worlds. The seed is stored per session.

6. Backend

6.1 Services

Service Role
API Gateway Auth, rate limits, per-tier queueing
Catalog and Licensing Tracks, universes, rights records, territory checks, kill switches
Theme Service Orchestrates a request end to end, streams results to the client over SSE
Variant Selector Embedding search plus seeded sampling
Planner LLM with JSON-schema-constrained output. Produces the theme spec. A 2.5 s timeout falls back to a deterministic rule planner using the top pooled variant
Asset Resolver Vector search over pools (pgvector or similar)
Generator workers GPU autoscaling pool
Moderation Input and output safety checks
Packager Compression and bundling, pushed to CDN

6.2 Request lifecycle

  1. Client posts the descriptor (and optional keyframe) with a track ID and seed.
  2. Catalog checks the license and territory, then returns the universe and variants.
  3. Variant Selector picks the variant. The Planner writes the spec (surface looks, prop mappings, lighting, atmosphere, ambience).
  4. The Asset Resolver matches each item against the pools. Pool hits return immediately. Misses go to the generator queue.
  5. Results stream in stages: spec and pooled textures first (target ≤ 3 s after upload), then generated textures, then props as each finishes.

6.3 Generation pipeline

  • Textures: few-step distilled diffusion with circular padding for seamless tiling, then upscale, then derive normal and roughness maps. Auto-QA covers seam score, style match against the style bible, and a safety classifier. Passing textures enter the pool, so the pool grows with use. Target depth is 200+ per (variant, surface).
  • 3D props: a curated .glb library (≤ 20k triangles, one material, 512² textures, meshopt-compressed). Hero props can use image-to-3D models in the background (10 to 60+ s). They enter the pool only after QA.
  • Packaging: KTX2 textures (ASTC/ETC2), meshopt .glb, manifest, signed CDN URLs.

6.4 Infrastructure

Kubernetes, with Redis Streams or SQS for queues, Postgres plus pgvector, object storage plus CDN, GPU node pools autoscaled on queue depth, and remote config and feature flags for tier tables and universe kill switches. Cache key: (universe, variant, scene_cluster, tier). When the GPU queue is long, serve a pooled bundle rather than make the user wait.

8. Timeline of one session

Time Client Server
T+0 Camera opens, base look from the bundled pack applies at once none
T+0 to 3 s Guided scan, descriptor and clean plate built none
T+3 s Descriptor uploaded (async) Licensing check, variant selection, planner starts
T+4.5 s Spec received, pooled textures stream in, crossfade over 400 ms Generation for pool misses starts
T+6 to 10 s Fresh textures fade in Packaging and CDN push
T+10 to 40 s Props appear one by one Background hero-prop generation
Record Theme frozen, voice and track mixed, export Optional Studio render

Offline or slow network: the base look stays in place and the bundled default pack is used. The preview is never blocked.

9. Privacy and security

  • Data minimization: the descriptor is numeric and non-identifying. Face landmarks and raw video never leave the device. The keyframe is opt-in, face-excluded, processed in memory and deleted after processing (retention window in the policy).
  • Privacy mode: descriptor-only, with lower personalization, available to every user.
  • Consent and compliance: explicit in-app consent for scene upload, and a privacy policy written for GDPR and India's DPDP Act 2023. Minors need an age gate and verifiable parental consent where the law requires it. Counsel must confirm biometric-law exposure (face landmarks are processed on device only, which should limit it).
  • Transport and storage: TLS, certificate pinning, signed short-lived CDN URLs, encryption at rest, per-user rate limits, and abuse detection on upload endpoints.
  • Model and asset integrity: signed model and theme bundles, with checksum verification before load.

10. Rights, licensing and moderation

This is the highest non-technical risk and needs counsel and business development from day one.

  • Music and dialogue: licenses from labels, publishers, performing-rights organizations and film/TV rights holders, per territory. The catalog service enforces territory and expiry, with a remote kill switch per track.
  • Universe likeness: recreating a franchise's locations, props and visual identity usually needs the rights holder's approval. Each Universe Pack carries a mode: licensed (official style bible, named locations) or inspired (generic genre looks such as "dark medieval fortress" with no names, logos or characters).
  • Generation guardrails: prompt sanitizer, negative lists (logos, characters, actors' likenesses), output classifiers for IP leakage and unsafe content, and a human review queue sampling pool entries before they are promoted.
  • User content: classifiers on the keyframe path skip personalization for unsafe scenes. A takedown and reporting flow is required for UGC.

11. Quality, testing and observability

  • Device lab: a matrix across chipsets (Snapdragon, Dimensity, Exynos, Unisoc), RAM (2 to 12 GB) and Android versions, including genuinely cheap phones from week one.
  • Golden scene set: varied rooms, lighting, skin tones, clutter and camera motion, used for mask IoU, flicker score and visual regression runs in CI.
  • Runtime metrics: time to first theme and to final theme, fps p50/p5, dropped frames, thermal throttling events, battery per minute, crash-free rate, cache hit rate, generation cost per session, moderation reject rate, export success rate.
  • Experimentation: remote-config tier tables and A/B tests on variant selection, with guardrails on frame rate and cost.

13. Risks and mitigations

Risk Mitigation
Franchise and music rights block launch Start with licensed or original-IP universes, ship inspired mode, build the licensing pipeline early
Weak phones can't hold frame rate Tier L as the baseline, governor, cheap-device testing from day one
Mask flicker and edge artifacts Temporal smoothing, edge-aware upsampling, clean-plate fallback, dedicated tuning sprints
Generation cost grows with users Pooled assets, cache keys, generate-on-miss only, per-tier queues
Slow or unreliable networks Bundled base look, staged streaming, offline default pack
Privacy backlash Descriptor-first design, privacy mode, opt-in keyframe, clear consent copy
Unsafe or off-brand generations Layered moderation, human sampling before pool promotion, per-universe kill switch
Thermal throttling on long recordings Governor, adaptive cadence, battery-aware downgrades

14. Open decisions

  1. First 3 universes and whether each launches licensed or inspired.
  2. Keyframe upload: opt-in by default, or descriptor-only until the quality gain is proven in beta.
  3. On-device vs. self-hosted vs. managed LLM for the Planner (cost and latency trade-off).
  4. Build vs. buy for face tracking and the 3D renderer (Banuba, DeepAR, Camera Kit vs. in-house).
  5. Studio render: included in a subscription tier or sold per clip.
