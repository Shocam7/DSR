DubSmash Reborn: Flutter Engineering Guide (Agent Playbook)

Companion to the Technical Blueprint · Flutter UI + native Android engine · Android only

0. How the agent uses this guide

  1. Always read §1 to §5 before any task. They are the rules. §6 is the work: do one milestone at a time, in order.
  2. Each milestone has Tasks and a Gate. Do not start the next milestone until every Gate item passes and is recorded in PROGRESS.md.
  3. Work in small PRs (one task each). Each PR must include tests, pass flutter analyze, and update PROGRESS.md.
  4. Stop and ask the human before: adding a dependency, changing a schema or the Pigeon contract, changing anything that sends user data off-device, missing a performance budget by more than 20%, or making any licensing/content decision.
  5. When a requirement is unclear, write the assumption in DECISIONS.md and continue. Do not stall on small questions.
  6. Verify current package and API versions against official docs at M0 and pin them. Do not trust remembered versions.

1. Invariants (never violate)

  • No video frames cross the Dart boundary. Pixels stay in native GPU memory. Dart sends commands and receives small events (≤ 2 Hz).
  • The preview never waits on network or ML. The render loop uses the latest available masks and theme.
  • Faces and raw video never leave the device. Only the scene descriptor (and an opt-in, face-excluded keyframe) may be uploaded.
  • The theme is frozen at record start and version-pinned, so export equals preview.
  • Every effect has a Tier L fallback or is disabled on Tier L. No feature ships without a degradation path.
  • Dart is the shell. Kotlin (and C++ only after profiling proves a need) is the engine.

2. Architecture: what lives where

Layer Owns
Dart / Flutter UI, navigation, state, catalog, auth, licensing checks, networking (catalog, theme requests, SSE), downloads and cache, analytics, remote config, permissions flow, settings
Native engine (Kotlin), dsr_engine plugin CameraX, EGL/GL render thread, ML inference, scene scan and descriptor, theme runtime, compositing, governor, MediaCodec recording, Oboe audio, Filament props
Native C++ (optional) Hot loops only (mask smoothing, clean-plate median) once a profile shows Kotlin cannot meet budget
Backend Separate repo and guide. The app talks to it through the contract in the Blueprint (§7). Use the mock server until it exists

Preview path: CameraX → GL external texture → compositor (FBO) → blit to (a) the Flutter SurfaceProducer surface and (b) the MediaCodec input surface when recording. Dart shows it with a Texture(textureId: ...) widget. Do not use the camera plugin or platform views for the effects path.

Stack decisions (fixed unless the human changes them): Riverpod (state), go_router, Dio (HTTP), drift (local DB), freezed + json_serializable, Pigeon (typed native contract), Firebase Crashlytics + Remote Config, flutter_secure_storage, permission_handler. minSdk 26, targetSdk latest, arm64-v8a and armeabi-v7a ABIs (cheap phones are still often 32-bit; confirm with the human before dropping v7a).

Dart code depends on an EngineApi interface in lib/engine/. Production uses the Pigeon-backed implementation, and tests use FakeEngineApi. This lets the whole UI be built and tested without native code.

4. Native ↔ Dart contract

Texture. createSession returns a textureId from TextureRegistry.createSurfaceProducer(). Native must handle the producer's surface-created and surface-destroyed callbacks by recreating the EGL window surface. Dart wraps the Texture in an AspectRatio and never rebuilds it per frame.

Commands (Pigeon @HostApi), sketch:

@HostApi()
abstract class EngineHostApi {
  @async SessionInfo createSession(SessionConfig c);       // textureId, previewSize, tier
  @async void startPreview(int sessionId);
  void stopPreview(int sessionId);
  void startScan(int sessionId);
  @async String finishScan(int sessionId);                  // descriptor JSON (<50 KB)
  void applyTheme(int sessionId, String themeDir, ThemeStage stage, int crossfadeMs);
  void setTierOverride(int sessionId, Tier? tier);          // debug and A/B
  @async void startRecording(int sessionId, RecordingConfig c);
  @async RecordingResult stopRecording(int sessionId);      // file path, duration, theme_id
  void disposeSession(int sessionId);
}

@FlutterApi()
abstract class EngineFlutterApi {
  void onStats(FrameStats s);      // ≤ 1 Hz: fps, ml ms, tier, thermal
  void onEvent(EngineEvent e);     // scanProgress, tierChanged, themeStageReady, error
}

Rules: payloads are small and typed, errors use typed EngineError codes (never raw exception strings), every call is idempotent where possible, and disposeSession must release camera, GL, codecs and models within 500 ms.

Theme handoff. Dart downloads and verifies theme bundles (checksum, signature), writes them to app storage, and passes a directory path to native. Native reads the manifest (schema v1) and never touches the network.

Flavors: dev (mock server, debug HUD on), staging, prod. CI runs analyze, Dart tests, native unit tests, and builds the APK on every PR. Instrumented tests run on the device lab or Firebase Test Lab nightly.

Reference devices (the human supplies exact models at M0): L (2 GB RAM, Helio G35 / Unisoc class), M (Snapdragon 6xx / Dimensity 700 class), H (current flagship). All Gates are measured on L and M at minimum.

6. Milestones

M0: Bootstrap and guardrails

Tasks

  • Create the Flutter project, flavors, strict analysis_options.yaml, folder layout (§3), CI workflow, PROGRESS.md, DECISIONS.md.
  • Create the dsr_engine plugin with Pigeon codegen and the Dart EngineApi interface plus FakeEngineApi.
  • Build tool/mock_server (catalog list, track download, /theme SSE that streams stages with canned bundles).
  • "Hello texture": native renders an animated GL color into a SurfaceProducer, shown by a Flutter Texture.

Gate: CI green; APK installs on L and M; hello texture runs at 30+ fps and survives rotate, background/foreground, and 20 session create/dispose cycles with no native memory growth.

M1: Camera → GL → Flutter

Tasks

  • CameraX with a plugin-owned LifecycleOwner driven by Activity callbacks, front/back switch, orientation, zoom/tap-focus later.
  • Camera frames to an external OES texture, then the compositor FBO (passthrough shader), then the producer surface. Own the EGL context and render thread.
  • Dart permission flow (camera, mic), RecordScreen showing the preview, debug HUD (fps, frame ms) from onStats.

Gate: preview matches device camera fps on L and M; no leaks after 30 min; correct behavior on pause/resume, permission denial, surface loss; Flutter UI stays at 60 fps with the preview running.

M2: Recording and audio core

Tasks

  • Second EGL window surface from MediaCodec (H.264, HEVC optional), 1080p30 with fallback to 720p on Tier L.
  • Audio via Oboe: track playback, mic capture, headphone detection, AEC in speaker mode, mixer, MediaMuxer.
  • One-time latency calibration screen, with offset stored per device and applied at mux.
  • Dart: record/stop, countdown, trim, local library (drift).

Gate: a 60 s recording plays back correctly on L and M; A/V offset ≤ 40 ms after calibration; no dropped-frame spikes above 5% during encode; recorded file opens in the system gallery.

M3: Person segmentation and basic compositing

Tasks

  • ML module: model loader with checksum check, delegate chooser (NPU → GPU → XNNPACK) with a first-launch micro-benchmark cached per model.
  • Person mask (MediaPipe) every 1 to 2 frames on the ML thread; "latest result" buffer; temporal smoothing and edge-aware upsample in a shader.
  • Shader effects driven by the mask: background color/blur. Governor skeleton (rolling frame time, thermal status).

Gate: mask p95 latency and IoU on the golden scene set meet targets recorded in PROGRESS.md (set the baseline here); edge flicker score below threshold; render fps unaffected by ML load.

M4: Scene segmentation and theme runtime

Tasks

  • Scene segmentation (wall/floor/ceiling/window/furniture), tiered resolution and cadence.
  • Theme Runtime: parse manifest schema v1, load KTX2/ASTC textures, tile onto masks, lighting transfer (lum(frame)/mean_lum(region)), crossfade between themes, memory budget per tier.
  • Bundled "base look" pack and two hand-authored test themes. Tier L / M / H config table loaded from Remote Config with a bundled default.
  • Full governor: degradation order (depth → props → mask res/cadence → particles → tier) with hysteresis.

Gate: a retextured wall holds ≥ 24 fps on L and ≥ 30 fps on M; lighting visibly preserved across 3 test rooms; governor downgrades and recovers correctly under a forced-load test.

M5: App shell and catalog (Dart; may run parallel to M3 and M4)

Tasks

  • Auth, catalog browse/search, track detail, download manager with resume, Universe Pack parsing (style bible metadata, base look, cue track, rights record).
  • Licensing client: territory and expiry checks, kill-switch honored from Remote Config.
  • Feed/share screens, edit screen, settings (privacy mode, keyframe consent, quality override).

Gate: widget and integration tests pass against mock server; expired or out-of-territory tracks are blocked in the UI; offline launch works with cached catalog.

M6: Scan, descriptor and server theming

Tasks

  • Guided scan UX (Dart) driving native startScan; native builds the descriptor (class areas, objects if M7 is done, palette, lighting) and a clean plate.
  • Descriptor upload (Dio), SSE client for staged results, bundle download with checksum and signature check, theme cache (LRU), crossfade apply.
  • Fallbacks: timeout, offline, server error all keep the base look. Seed and theme-version pinned per session.

Gate: end-to-end against the mock server, then the real server; first themed look ≤ 1 s, personalized p50 ≤ 8 s on the lab network; no preview stutter during download/apply; privacy mode sends no keyframe.

M7: Object swaps (Tier M/H)

Tasks

  • Object detection (instances) every N frames plus optical-flow tracking; class → asset mapping from the theme.
  • Fill original pixels from the clean plate, then render the replacement via Filament into an offscreen texture composited at the tracked box with depth ordering.
  • Per-tier cap on number of props; asset loading off the render thread.

Gate: bottle→goblet style swap stays locked to the object while the camera is still; no halo of the original object; frame-rate budgets still hold on M.

M8: Atmosphere, cue-sync and relight

Tasks

  • Color-grade LUT, fog, GPU particles (embers/snow/dust), window/sky replacement.
  • Cue track playback: beat grid and line timestamps drive effect triggers; person relight (tint and rim light) from the theme.

Gate: effects sync to the audio within ±1 frame at 30 fps on a test track; all effects respect governor downgrades.

M9: Depth, ARCore (optional) and Studio render

Tasks

  • ARCore plane and depth when the device supports it, behind a capability check, with a segmentation-only fallback.
  • Studio render: upload masks and theme reference for a server-side high-quality re-render (premium). Gate behind a feature flag.

Gate: devices without ARCore behave identically to M8; flag off by default.

M10: Hardening and release

Tasks

  • 60 min soak tests on L, M, H; thermal tests; low-memory kill and restore; Crashlytics wired with engine breadcrumbs.
  • Play readiness: Data Safety form matches actual data flows, privacy policy, age gate, consent copy, target API compliance, 16 KB page-size support for all native libraries (verify current Play requirements), App Bundle size and model delivery plan.
  • Staged rollout plan with remote kill switches per universe and per effect.

Gate: crash-free ≥ 99.5% in beta; all budgets in §7 met on L and M; security and privacy checklist signed off by the human.

7. Cross-cutting standards

Performance budgets (targets; revise after the M1 baseline and record changes in DECISIONS.md)

Item Tier L Tier M/H
Preview fps ≥ 24 ≥ 30
GL render time per frame ≤ 14 ms ≤ 12 ms
Flutter UI frame (build + raster) ≤ 8 ms ≤ 8 ms
App memory (PSS) while recording ≤ 350 MB ≤ 600 MB
Theme bundle on disk ≤ 8 MB ≤ 25 MB
Cold start to camera ≤ 2.5 s ≤ 1.5 s

Testing pyramid

  • Dart: unit tests for domain logic; widget tests with FakeEngineApi; golden tests for key screens; integration tests against the mock server.
  • Kotlin: JUnit for descriptor builder, governor, theme manifest parser, cue scheduler (pure logic, no GL).
  • On-device: instrumented tests for lifecycle (create/dispose loops), and a benchmark harness that runs a recorded clip through the pipeline and writes frame times and mask metrics to JSON for CI comparison.
  • Quality set: a golden scene dataset (varied rooms, lighting, skin tones, clutter). Mask IoU and flicker score gate regressions.

Telemetry (privacy-safe, no images): time to first/final theme, fps p50/p5, tier and downgrades, thermal events, crash breadcrumbs, delegate chosen, cache hit, export success.

Errors: a typed EngineError enum (permission, cameraBusy, surfaceLost, modelLoadFailed, delegateFailed, encoderFailed, themeInvalid, oom). The UI maps each to a recoverable message. Native never crashes the app for a failed effect. It disables the effect and reports.

Security: signed theme and model bundles, checksum verify before load, TLS with pinning, signed CDN URLs, tokens in secure storage, no secrets in the repo (use --dart-define-from-file).

Code standards: feature-first folders, immutable state (freezed), no business logic in widgets, no print (use the logger), every public Dart API documented, every native class has a single owner thread documented in its header comment.

8. Known Flutter + Android pitfalls

  • Surface lifecycle: the Flutter texture surface can be destroyed and recreated (app background, config change). Recreate the EGL window surface, never the whole session.
  • EGL context loss after backgrounding on some devices: detect, rebuild textures and shaders from cached sources.
  • Hot reload does not restart native code. After native changes, do a full restart. Agents must not assume a Dart hot reload applied them.
  • Competing for the GPU: on Tier L, Flutter's own rendering competes with the effects pipeline. Avoid BackdropFilter, large blurs and heavy animations over the preview. Use RepaintBoundary and const widgets for overlays.
  • Model files: set noCompress for .tflite in Gradle, or loading is slow and memory-heavy.
  • Channel traffic: never send per-frame data. Batch stats to ≤ 1 Hz.
  • Delegates: GPU delegates can be slower than CPU or fail on specific chips. Trust the micro-benchmark, not assumptions, and cache the result per device and model version.
  • Thermal and battery: long recordings throttle. The governor must react before the OS does.
  • Permissions: handle "denied", "denied forever" and "revoked while running" paths. Test each.
  • Audio focus and Bluetooth: headset connect/disconnect mid-session changes latency. Re-run offset logic and warn the user.
